# Air780EPV 短信转发器

## 这是什么

一台插着 SIM 卡的 Air780EPV，把收到的短信转发到邮箱。

链路：**短信 → (4G) → pushplus → 邮件**，全程本地运行，不需要自建服务器、不需要公网 IP。

典型用途：家里/店里那台设备的验证码、运营商通知、银行短信，不用一直盯着手机。

## 为什么值得一看

这不是"又一个转发脚本"，而是一台**会被长期无人值守运行的小设备**：

- **单灯表达 4 种状态**（正常 / 无网 / 积压 / 死了），站在设备前一眼判断
- **崩溃全兜底**：所有任务体 pcall，不会因为一个异常把整机重启
- **断网先存队列后重试**，不丢即时消息
- **邮件里自动提取验证码**，放在最上方

`CHANGELOG.md` 里记的每一次改动都写了"为什么"，那是排错时最有用的部分。

| SIM | 联通 460/01，Band 3 |
| 脚本 | `sms-forwarder` v3.5.3 |

### 固件库清单（重要）

`[caps]` 那行开机就会打印，实测结果：

```
可用: http sms socket mobile json pm wdt gpio mcu rtos io
缺失: fskv uart
```

**缺 `fskv` 的影响**：队列只能用内存，设备重启时未发出的消息会丢。
**缺 `uart` 的影响**：无法用 UART1 外接探针/日志转发。

> ⚠️ 这个固件是**云编译**产物，不是官方发布版。官方 EPV 正式固件止于 `V1002_EC718PV`，
> 之后的 EPV 固件都要自己云编译（luatos.com → 在线编译，芯片选 `@EC718PV`）。

## 三、指示灯（现场判断的唯一手段）

单个 LED（GPIO 27）。不接电脑、不看日志，靠它判断状态。

### 四种基础状态

| 表现 | 含义 | 处理 |
|---|---|---|
| **慢闪**（2 秒 1 下） | 正常：有网、队列空 | 无需处理 |
| **快闪**（1 秒 5 下） | 网络未就绪，正在重连 | 等；持续几小时则查信号/卡 |
| **两段闪**（见下） | 队列积压：收到了但发不出去 | 看第二段几下 |
| **灭着** | 程序没在跑（死了 / 正在重启） | **最强故障信号**，接串口看日志 |

插播（不改变主节奏）：慢闪中插 **1 下** = 刚收到短信；插 **2 下** = 刚发送成功。

### 积压时的"两段闪"

```
[闪 2 下]  停 1.2 秒  [闪 N 下]  停 2.5 秒      ← 每 5 秒一轮，循环
    ↑固定 2 下 = 有积压        ↑N = 故障码
```

| N | 含义 | 性质 |
|---|---|---|
| 无（只有 2 下） | 原因未知 | — |
| **1** | 连不上服务器（HTTP -1/-4/-5/-6/-7） | 网络侧 |
| **2** | 超时（HTTP -8） | 网络侧 |
| **3** | pushplus 拒绝（接口返回非 200） | 服务端/配置 |
| **4** | token 空 / 渠道无效 | 配置 |
| **5** | **消息被丢弃**（重试超限，或队列满丢最旧） | **不可逆损失** |
| **6** | **调用异常**（http 库抛错/卡住） | **代码或库问题** |

**判读要点**：1/2/3/4/5 是环境或配置问题，只有 **6** 是代码问题。

极性：`config.LED_ACTIVE = 1` 表示高电平亮。若现象相反改成 `0`。

## 五、烧录（重要）

**只点「仅下载脚本」，永远不要点「全量下载(底层+脚本)」。**

脚本区写坏可以重下；但拿错型号的 `.soc` 做全量下载会变砖。

步骤：

1. 项目管理 → **删除全部** → **增加目录(递归)** → 选本目录
2. 确认文件个数对（**9 个**：8 个 .lua + config.lua）
3. **语法检查**
4. 回主界面 → 当前项目选中 → **仅下载脚本**
5. 烧录期间**取消勾选「4G模块USB打印」**（USB 反复枚举会触发旧固件的看门狗复位）

> ⚠️ 项目里的文件是**逐个登记**的。新增 `.lua` 后不重新"增加目录"，
> 下载时会报 `缺少 xxx.lua 请添加`（这比烧进去崩掉好，但会白折腾一次）。

> ⚠️ 备用固件：`LuatOS-SoC_V2002_EC718PV_CLOUD.soc`（本机已有，7.4 MB）

## 六、已知限制

1. **队列不持久**：`fskv` 缺失，重启会丢未发出的消息（正常 1~2 秒就发完，窗口极小）。
2. **来电**：脚本完全不碰通话路径（不注册 `cc`）。若固件/供电层仍会因来电复位，只能从 SIM 侧解决（换物联卡 / 关语音功能）。
3. **无自愈**：不设定时重启、不做网络探测重启。网络僵死时只能靠**灯变双闪**现场发现。
4. **无时钟同步**：没有 NTP。短信时间用的是短信元数据，不依赖设备时钟。

## 七、踩坑记录（换固件/换型号时最容易再踩）

1. **`_G[name]` 在 LuatOS 里不可靠** —— 会把存在的库读成 nil。判断库是否可用要直接读全局变量。
2. **LuatOS 的库很多是 userdata 不是 table**（`sms`、`gpio` 都已实测）—— 任何 `type(x)=="table"` 的判断都会误判，必须用 `pcall` 取字段。
3. **未捕获的 Lua 错误 = VM 退出 = 15 秒后重启**，而且会循环（间隔 16.2 秒）。所有任务体、回调体都要 `pcall`。
4. **HTTP 超时必须小于看门狗**（本项目 6 秒 vs 10 秒）。否则网络一卡就是重启，永远看不到超时错误码。
5. **不要用定时重启** —— 每次重启有约 1 分钟离线窗口，落在这个窗口的短信会漏，而且漏了没提示。
6. **不要自己切飞行模式** —— 会和固件自愈抢射频，已知会酿成死亡螺旋。
7. **pushplus 的 txt 模板换行会被吞** —— 邮件按 HTML 渲染，必须用 `html` 模板 + `<br/>`。
8. **pushplus 返回 200 只代表受理**，投递是异步的；真正确认要看邮箱。
