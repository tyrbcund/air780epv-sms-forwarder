# Air780EPV 短信转发器

## 这是什么

一台插着 SIM 卡的 **Air780EPV**，把收到的短信转发到邮箱。

链路：**短信 → (4G) → pushplus → 邮件**，全程本地运行，不需要自建服务器、不需要公网 IP。

典型用途：家里/店里那台设备的验证码、运营商通知、银行短信，不用一直盯着手机。

## 为什么值得一看

这不是"又一个转发脚本"，而是一台**会被长期无人值守运行的小设备**：

- **单灯表达 6 种故障码**（连不上 / 超时 / 被拒 / 配置错 / 丢消息 / 程序异常），站在设备前一眼判断
- **五层自愈**：固件自愈 → 定时切飞行模式 → 失败切飞行模式 → 重启整机 → 定时重启
- **队列持久化**：短信先落 Flash 再发，断电重启会自动补发
- **崩溃全兜底**：所有任务体 `pcall`，不会因为一个异常把整机重启

排障过程和固件选型的完整记录见 **[docs/排错与固件选型.md](docs/排错与固件选型.md)**（带引用来源）。

## 一、运行环境（实测）

| 项目 | 值 |
|---|---|
| 模组 | Air780EPV_A12 |
| 芯片 | EC718PV（Cat.1 bis，`am_get_chip_type` 输出） |
| 固件 | `LuatOS-SoC_V2001_EC718PV_CLOUD`<br>base 23.11 / bsp V2001 / Build 2024-12-01 |
| SIM | 联通 460/01，Band 3 |
| 脚本区 | 64 KB（V2001）／128 KB（V1002、V2002、V2003） |
| Lua 堆 | 128 KB |

### 固件库清单（开机自动打印）

```
[caps] 可用: http sms socket mobile fskv json pm wdt gpio uart mcu rtos io
[main] 缺库=0
```

**换固件是必须的**：原机固件（V2003）缺 `fskv` 和 `uart`，导致队列无法持久化、也没有 AT 通道。
固件对比与选型见 [docs/排错与固件选型.md](docs/排错与固件选型.md#三固件对比与选型)。

## 二、文件职责

| 文件 | 干什么 |
|---|---|
| `config.lua` | **唯一需要改的文件**（不要提交到仓库！） |
| `config.example.lua` | 配置模板，复制成 `config.lua` 再填 |
| `main.lua` | 入口：能力探测、看门狗、自愈、发送主循环、内存监控 |
| `util_sms.lua` | 收短信、过滤、去重、排版、入队 |
| `util_queue.lua` | 待发队列（有 fskv 就持久化，没有降级内存） |
| `util_push.lua` | pushplus 推送（手拼 JSON，不依赖 json 库） |
| `util_http.lua` | HTTP 封装（超时 6 秒，必须小于看门狗） |
| `util_net.lua` | 网络就绪判断（兼容 userdata 库） |
| `util_lib.lua` | 库访问兼容层（table / userdata 都能取字段） |
| `led.lua` | 状态灯与故障码 |

## 三、指示灯（现场判断的唯一手段）

| 表现 | 含义 |
|---|---|
| **慢闪**（2 秒 1 下） | 正常：有网、队列空 |
| **快闪**（1 秒 5 下） | 网络未就绪，正在重连 |
| **两段闪** | 队列积压：`[2 下]` + 停 1.2 秒 + `[N 下]`，每 5 秒一轮 |
| **灭着** | 程序没在跑（死了 / 重启中） |
| 慢闪中插 **1 下** | 刚收到短信 |
| 慢闪中插 **2 下** | 刚发送成功 |
| 慢闪中**每 10 秒插 3 下** | 最近 30 分钟内丢过消息 |

**故障码 N**：

| N | 含义 | 性质 |
|---|---|---|
| 1 | 连不上服务器（-1/-4/-5/-6/-7） | 网络侧 |
| 2 | 超时（-8） | 网络侧 |
| 3 | pushplus 拒绝 | 服务端/配置 |
| 4 | token 空 / 渠道无效 | 配置 |
| 5 | **消息被丢弃** | 不可逆损失 |
| 6 | **调用异常** | 代码或库问题 |

> 1–5 是环境或配置问题；**只有 6 需要改代码**。

## 四、自愈阶梯

| 层 | 手段 | 触发 | 代价 |
|---|---|---|---|
| 1 | 固件自动重注册 | 掉网后 30 秒 | 无 |
| 2 | 定时切飞行模式 | 每 12 小时 | 约 2 秒断网 |
| 3 | 失败后切飞行模式 | 连续失败 2 次 | 约 2 秒断网 |
| 4 | 重启整机 | 连续失败 6 次（每天≤3 次） | 约 60 秒，队列不丢 |
| 5 | 定时重启 | 运行满 23 小时 | 约 60 秒，队列不丢 |

全部可在 `config.lua` 里调整或关闭（对应 `FLYMODE_INTERVAL`、`FAIL_FLYMODE_COUNT`、`FAIL_REBOOT_COUNT`、`REBOOT_AFTER_HOURS`）。

## 六、烧录

**只点「仅下载脚本」，不要点「全量下载」**（除非要换固件）。

1. 项目管理 → 删除全部 → 增加目录(递归) → 选本目录
2. 确认文件数（脚本 9 个 + `config.lua`）
3. 语法检查
4. 回主界面 → 当前项目选中 → 仅下载脚本

> ⚠️ 项目里的文件是**逐个登记**的，新增 `.lua` 后必须重新"增加目录"，否则报 `缺少 xxx.lua 请添加`。
> ⚠️ 烧录时关闭「4G模块USB打印」——USB 枚举抖动会触发旧固件的看门狗复位（详见 [docs](docs/排错与固件选型.md#3-usb-枚举抖动导致整机复位调试期假故障)）。

**换固件**时才用「全量下载(底层+脚本)」，且必须勾选「清除 fs」「清除 kv」，并先跑一遍 `tools/soc_inspect.ps1` 确认机型匹配。

## 七、已知限制

1. **不支持 HTTPS**：两个可得的 EPV 固件里 `LUAT_USE_TLS` 都是注释状态，只能走 `http://`（实测）。
2. **SMS 接收可能失效**：长时间运行后新短信可能不再触发回调，且**Lua 层无法感知**。
   只能靠第 3/4 层自愈在"有消息发不出去"时兜住（见 [docs](docs/排错与固件选型.md#2-sms-接收失效新短信完全不触发回调)）。
3. **来电**：脚本完全不碰通话路径（不注册 `cc`）。若固件/供电层因来电复位，需从 SIM 侧解决。
4. **无 NTP 定时对时**：短信时间取自短信元数据，不依赖设备时钟。

## 八、踩坑记录（换固件/换型号时最容易再踩）

1. **`_G[name]` 在 LuatOS 里不可靠** —— 会把存在的库读成 nil，判断库可用性要直接读全局变量。
2. **LuatOS 的库很多是 userdata 不是 table**（`sms`、`gpio` 实测）—— `type(x)=="table"` 会误判，必须用 `pcall` 取字段。
3. **未捕获的 Lua 错误 = VM 退出 = 15 秒后重启**，且会循环（16.2 秒一轮）。所有任务体、回调体都要 `pcall`。
4. **HTTP 超时必须小于看门狗**（本项目 6 秒 vs 10 秒），否则网络一卡就是重启而不是超时错误码。
5. **不要用定时重启掩盖问题** —— 必须有持久化队列兜底，否则每天漏 1 分钟短信。
6. **不要高频切飞行模式** —— 会与固件自愈抢射频；低频（12 小时）或失败触发才安全。
7. **pushplus 的 txt 模板换行会被吞** —— 邮件按 HTML 渲染，要用 `html` 模板 + `<br/>`。
8. **`.soc` 是 7z 包** —— 可以用 `tools/soc_inspect.ps1` 解包看 `luat_conf_bsp.h`，判断 TLS/FSKV/UART/VoLTE 是否编入。

## 九、工具

- `tools/soc_inspect.ps1`：固件体检。解包 `.soc`，打印分区、内存、编译开关，并给出"是否适合 EPV"的结论。
  用法：`powershell -ExecutionPolicy Bypass -File tools/soc_inspect.ps1 -Soc <路径>`，
  或把 `.soc` 拖到 `tools/固件体检.bat` 上。
